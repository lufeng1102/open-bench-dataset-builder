

# ds-cli 客户端操作手册

本文档面向第一次使用   `ds-cli`   的外部用户，介绍如何安装客户端、配置访问凭证，以及如何使用常见命令完成数据集查询、创建、克隆、修改、推送和发布。

## 1. ds-cli 是什么

  `ds-cli`   是数据集平台提供的命令行客户端。你可以在本地终端通过它访问数据集平台，常见用途包括：

- 查询数据集信息
- 查看数据集版本
- 克隆数据集到本地
- 创建新数据集
- 添加、更新、删除数据集样本和附加文件
- 推送本地变更到云端
- 申请发布数据集版本


它的使用方式类似 Git：先在本地准备数据和变更，再执行   `push`   同步到云端，最后通过   `release`   申请发布版本。

```
安装客户端 -> 配置 apikey -> 查询/克隆/创建数据集 -> 本地 add/update/rm -> push -> release
```



## 2. 前置条件

安装和使用   `ds-cli`   前，请先确认本地满足以下条件。

### 2.1 操作系统

当前客户端支持常见桌面和服务器系统：

- macOS
- Windows
- Linux




### 2.2 Python 版本

本地需要安装 Python，且版本必须大于等于   `3.9`  。

检查 Python 版本：

```
python --version
```

或：

```
python3 --version
```

期望输出类似：

```
Python 3.9.x
Python 3.10.x
Python 3.11.x
Python 3.12.x
Python 3.13.x
```

如果版本低于   `3.9`  ，请先升级 Python，或使用 Conda/Miniforge 创建一个 Python 3.9+ 环境。



### 2.3 网络要求

使用   `ds-cli`   时需要能够访问 Open-Bench 平台。

平台地址：

```
https://www.open-bench.net
```

如果公司网络、代理或防火墙限制了访问，需要先处理网络连通性问题。



### 2.4 API Key

外部用户需要先在 Open-Bench 平台注册账号并获取   `apikey`  。没有   `apikey`   时，客户端无法完成鉴权，会报“未找到apikey”或鉴权失败。

获取方式：

1. 打开 Open-Bench 平台：  [https://www.open-bench.net](https://www.open-bench.net)  
1. 如果已有账号，直接登录。
1. 如果没有账号，先注册账号，再登录。
1. 登录后进入：首页 -> 个人中心 -> 账号安全。
1. 找到“API Key 管理”。
1. 复制页面中的 API Key，后续写入本地   `ds.cfg`   配置文件。

### 3.4 强制使用官方 PyPI

有些电脑的 pip 默认配置了阿里云、清华源或公司内部源。由于镜像源可能没有同步到最新安装包，直接执行   `pip install aispeech-ds-cli`   可能会提示找不到版本。

建议安装时显式指定官方 PyPI：

```
python -m pip install --no-cache-dir -i https://pypi.org/simple aispeech-ds-cli
```

如果本机配置较复杂，可以使用隔离模式忽略用户级 pip 配置和环境变量：

```
python -m pip install --isolated --no-cache-dir -i https://pypi.org/simple aispeech-ds-cli
```

如果仍然安装失败，请先检查当前 pip 实际使用的源：

```
python -m pip config list -v
```

### 3.5 macOS 系统自带 Python 说明

部分新版 macOS 会通过 Command Line Tools 提供 Python 3，例如：

```
/Library/Developer/CommandLineTools/usr/bin/python3
```

这个 Python 版本可能满足   `ds-cli`   的最低要求，但常见问题是：

- 终端里没有   `python`   命令，只有   `python3`  。
- 终端里没有   `pip`   命令，只有   `pip3`  。
-   `pip`   版本较旧，例如 21.x。
-   `python`  、  `python3`  、  `pip`  、  `pip3`   指向的不是同一个 Python 环境。


建议先确认当前命令路径：

```
which python
which python3
which pip
which pip3
python3 --version
python3 -m pip --version
```

如果确认要使用 macOS Command Line Tools 自带的 Python，可以把它加入当前 shell 的   `PATH`  ，并将   `python`   设置为   `python3`  ，将   `pip`   设置为   `pip3`  。

macOS 默认 shell 通常是 zsh，执行：

```
touch ~/.zshrc
printf '\nexport PATH="/Library/Developer/CommandLineTools/usr/bin:$PATH"\n' >> ~/.zshrc
printf 'alias python=python3\n' >> ~/.zshrc
printf 'alias pip=pip3\n' >> ~/.zshrc
source ~/.zshrc
```

然后确认：

```
python --version
pip --version
```

升级 pip 并安装   `ds-cli`  ：

```
python -m pip install -U pip -i https://pypi.org/simple
python -m pip install --no-cache-dir -i https://pypi.org/simple aispeech-ds-cli
```

如果执行   `python3 -m pip --version`   提示没有 pip，建议优先安装官方 Python 3.9+、Homebrew Python 或 Conda/Miniforge Python，再重新执行安装命令。

## 4. 配置 API Key

  `ds-cli`   会从当前用户家目录下的   `.OREF/ds.cfg`   文件读取   `apikey`  。

请先登录 Open-Bench 平台获取 API Key：

```
http://www.open-bench.org/home
```

操作路径：

```
首页 -> 个人中心 -> 账号安全 -> API Key 管理
```

复制 API Key 后，再写入本地配置文件。

配置文件路径：

```
~/.OREF/ds.cfg
```

其中   `~`   表示当前用户的家目录。

### 4.1 macOS / Linux 配置

```
mkdir -p ~/.OREF
printf 'apikey=你的apikey\n' > ~/.OREF/ds.cfg
```

查看文件内容：

```
cat ~/.OREF/ds.cfg
```

内容格式必须类似：

```
apikey=xxxxxxxxxxxxxxxx
```

> 

### 4.2 Windows 配置

Windows 用户需要在当前用户目录下创建：

```
C:\Users\<你的用户名>\.OREF\ds.cfg
```

文件内容：

```
apikey=xxxxxxxxxxxxxxxx
```

PowerShell 示例：

```
mkdir $HOME\.OREF
Set-Content -Path $HOME\.OREF\ds.cfg -Value "apikey=你的apikey"
```

查看文件内容：

```
Get-Content $HOME\.OREF\ds.cfg
```

> 

### 4.3 配置注意事项

- 文件名必须是   `ds.cfg`  。
- 目录名必须是   `.OREF`  。
- 配置项名称必须是小写   `apikey`  。
- 推荐只写一行：  `apikey=你的apikey`  。
-   `apikey`   前后不要加引号。
- 不要把   `ds.cfg`   放在项目目录下，客户端默认读取的是用户家目录下的配置文件。

## 6. 命令总览

查看全部命令：

```
ds-cli -h
```

外部用户常用命令如下：

|命令|作用|
|---|---|
|  `info`  |查询数据集信息|
|  `version`  |查看数据集版本列表|
|  `clone`  |克隆数据集到本地|
|  `create`  |创建数据集|
|  `add`  |添加数据集数据到本地暂存区|
|  `update`  |更新数据集数据到本地暂存区|
|  `rm`  |删除数据集数据到本地暂存区|
|  `push`  |推送本地暂存区变更到云端|

全局调试参数：

```
ds-cli --debug <命令>
```

例如：

```
ds-cli --debug info -n SlideSpeech
```

## 7. 常用命令说明与示例

### 7.1 查询数据集信息：info

按数据集名称查询：

```
ds-cli info -n SlideSpeech
```

按数据集 ID 查询：

```
ds-cli info -id ds2026070904135ZV3
```

如果当前目录已经是一个本地数据集目录，也可以直接执行：

```
ds-cli info
```



### 7.2 查看版本列表：version

按数据集名称查看版本：

```
ds-cli version -n SlideSpeech
```

按数据集 ID 查看版本：

```
ds-cli version -id ds2026070904135ZV3
```

在本地数据集目录中查看当前数据集版本：

```
cd SlideSpeech
ds-cli version
```



### 7.3 克隆数据集：clone

克隆数据集：

```
ds-cli clone SlideSpeech
```

克隆后会在当前目录创建一个同名数据集目录，例如：

```
SlideSpeech/
  .ds_cache/
  raws
  extras/
  sample_files/
```

克隆时复制指定文件或目录：

```
ds-cli clone SlideSpeech -cf sample/audio001.wav
```

克隆时复制全部文件：

```
ds-cli clone SlideSpeech -cf '*'
```



### 7.4 创建数据集：create

创建一个空数据集：

```
ds-cli create -n my_dataset_demo -zhn "我的测试数据集"
```

创建数据集并同时提交数据集描述文件：

```
ds-cli create -n my_audio_dataset -zhn "我的音频数据集" -df dataset.jsonl
```

创建数据集并同时提交数据集描述、样本文件和附加文件：

```
ds-cli create \
  -n my_audio_dataset \
  -zhn "我的音频数据集" \
  -df dataset.jsonl \
  -sf sample.jsonl \
  -ef extra.jsonl
```

创建成功后，会在当前目录生成本地数据集目录：

```
my_audio_dataset/
```

后续   `add`  、  `update`  、  `rm`  、  `push`   可以进入该目录后执行。



### 7.5 添加数据：add

  `add`   会把变更写入本地暂存区，不会立即同步到云端。执行成功后，需要再执行   `push`  。

进入本地数据集目录：

```
cd my_audio_dataset
```

添加数据集描述：

```
ds-cli add -df ../dataset.jsonl
```

添加样本数据：

```
ds-cli add -sf ../sample.jsonl
```

添加附加文件：

```
ds-cli add -ef ../extra.jsonl
```

一次添加多类文件：

```
ds-cli add -df ../dataset.jsonl -sf ../sample.jsonl -ef ../extra.jsonl
```

> 截图占位：  `add`   命令执行成功截图

### 7.6 更新数据：update

  `update`   用于更新已有数据集描述或已有样本标注。

更新数据集描述：

```
ds-cli update -df ../dataset_update.jsonl
```

更新样本标注：

```
ds-cli update -sf ../sample_update.jsonl
```

一次更新数据集描述和样本：

```
ds-cli update -df ../dataset_update.jsonl -sf ../sample_update.jsonl
```

执行成功后，需要继续执行：

```
ds-cli push
```



### 7.7 删除数据：rm

  `rm`   用于删除数据集描述项、样本标注或附加文件。

删除样本：

```
ds-cli rm -sf ../sample_rm.jsonl
```

删除附加文件：

```
ds-cli rm -ef ../extra_rm.jsonl
```

删除数据集描述中的部分字段：

```
ds-cli rm -df ../dataset_rm.jsonl
```

执行成功后，需要继续执行：

```
ds-cli push
```



### 7.8 推送变更：push

  `add`  、  `update`  、  `rm`   只是写入本地暂存区。要同步到云端，需要在本地数据集目录中执行：

```
ds-cli push
```

推送过程会上传文件、同步标注和附加数据。推送成功后，云端会产生临时版本或暂存变更，之后可以申请发布正式版本。



### 7.9 申请发布版本：release

申请发布时必须填写版本描述：

```
ds-cli release -m "初始化发布"
```

指定数据集名称发布：

```
ds-cli release -n my_audio_dataset -m "初始化发布"
```

指定数据集 ID 发布：

```
ds-cli release -id ds2026070904135ZV3 -m "初始化发布"
```

指定版本号发布：

```
ds-cli release -n my_audio_dataset -v v1.0.1 -m "补充 100 条样本"
```

如果不指定   `-v`  ，平台会自动推荐下一个版本号。



### 7.10 清空本地暂存区：clear

如果本地   `add`  、  `update`  、  `rm`   后还没有   `push`  ，并且想放弃这些本地变更，可以执行：

```
ds-cli clear
```

注意：  `clear`   只清理当前本地数据集目录下的暂存区变更。已经   `push`   到云端的内容不会被这个命令撤销。



## 8. 文件格式说明

  `ds-cli`   常用三类输入文件：

|文件参数|文件用途|常见文件名|
|---|---|---|
|  `-df, --dataset-file`  |数据集描述文件|  `dataset.jsonl`  |
|  `-sf, --sample-file`  |样本文件|  `sample.jsonl`  |
|  `-ef, --extra-file`  |附加文件|  `extra.jsonl`  |


这些文件一般使用 JSONL 格式，也就是“一行一个 JSON 对象”。

实际字段会根据数据集类型和服务端 schema 校验。下面示例用于帮助理解格式，最终以平台分配或服务端返回的 schema 为准。

### 8.1 dataset.jsonl 示例

音频数据集描述示例：

```
{"type":["audio"],"audio":{"tag":["speech"],"source":"record","speech":{"language":"zh"},"acoustic":{"channels":1,"sample_rate":16000}}}
```

文本数据集描述示例：

```
{"type":["text"],"text":{"tag":"nlu","language":"zh","source":"open_source","granularity":"sentence"}}
```

### 8.2 sample.jsonl 示例

音频样本示例：

```
{"sample_id":"sample_0001","attribute":{"path":"/Users/demo/data/audio/sample_0001.wav","file_type":"audio"},"annotation":[{"timestamp":{"begin_time":0,"end_time":1.23},"transcription":{"text":["你好"],"language":"zh"}}]}
```

文本样本示例：

```
{"sample_id":"text_0001","annotation":[{"transcription":{"text":["打开空调"],"language":"zh"}}]}
```

样本文件注意事项：

-   `sample_id`   在同一个样本文件中不能重复。
- 非文本类样本通常必须提供本地文件路径。
- 样本文件路径必须是绝对路径，例如   `/Users/demo/data/a.wav`   或   `D:\data\a.wav`  。
- 文件名不建议包含空格、单双引号等特殊字符。
- 长音频标注需要提供   `timestamp.begin_time`   和   `timestamp.end_time`  。
- 时间戳单位是秒。


### 8.3 extra.jsonl 示例

附加文件示例：

```
{"path":"/Users/demo/data/readme.txt"}
```

附加文件可以用于上传说明文档、补充材料等。

## 10. FAQ

### Q1：执行   `pip install aispeech-ds-cli`   报   `No matching distribution found`   怎么办？

常见原因有三个。

第一，Python 版本低于   `3.9`  。检查：

```
python --version
```

如果是 Python 3.8 或更低，请切换到 Python 3.9+。

第二，pip 没有访问正式 PyPI。可以强制指定正式 PyPI：

```
python -m pip install --no-cache-dir -i https://pypi.org/simple aispeech-ds-cli
```

第三，当前操作系统或 CPU 架构对应的安装包还没有发布。请联系工具维护方确认对应平台是否已发布。

### Q2：执行命令时报   `未找到apikey`   怎么办？

请检查配置文件是否存在：

```
ls ~/.OREF/ds.cfg
```

查看内容：

```
cat ~/.OREF/ds.cfg
```

正确格式：

```
apikey=xxxxxxxxxxxxxxxx
```

常见错误包括：

- 文件放到了项目目录，而不是用户家目录。
- 目录名写错，不是   `.OREF`  。
- 文件名写错，不是   `ds.cfg`  。
- 写成了   `api_key=xxx`  、  `APIKEY=xxx`   或其他名字。
-   `apikey`   为空。


### Q3：如何确认当前用的是哪个 Python 和 pip？

执行：

```
python --version
python -m pip --version
which python
which pip
```

Windows 执行：

```
python --version
python -m pip --version
where python
where pip
```

推荐始终使用：

```
python -m pip install aispeech-ds-cli
```

这样可以避免   `pip`   和   `python`   不是同一个环境。

### Q4：安装成功但   `ds-cli`   命令找不到怎么办？

通常是 Python 的脚本目录没有加入   `PATH`  。

先确认包是否已经安装：

```
python -m pip show aispeech-ds-cli
```

再重新打开终端。如果仍然不行，检查 pip 输出中的安装路径，把对应的   `bin`   或   `Scripts`   目录加入   `PATH`  。

### Q5：  `sample.jsonl`   里本地文件明明存在，为什么仍然报路径问题？

样本文件里的   `attribute.path`   必须使用绝对路径。

正确示例：

```
{"sample_id":"sample_0001","attribute":{"path":"/Users/demo/data/audio/sample_0001.wav","file_type":"audio"}}
```

不推荐：

```
{"sample_id":"sample_0001","attribute":{"path":"./audio/sample_0001.wav","file_type":"audio"}}
```

### Q6：  `add`   执行成功后，为什么平台上看不到数据？

  `add`   只会写入本地暂存区。需要继续执行：

```
ds-cli push
```

推送成功后，云端才会收到本地变更。

### Q7：  `push`   成功后，为什么还看不到正式版本？

  `push`   只是同步变更。需要继续执行：

```
ds-cli release -m "版本描述"
```

发布申请提交后，请在平台页面关注发布状态。

### Q8：执行命令时如何查看更多错误信息？

可以加   `--debug`  ：

```
ds-cli --debug info -n SlideSpeech
```

也可以查看当前目录下生成的日志文件：

```
ds_error.log
ds_info.log
```

### Q9：本地能不能手动创建   `/hpc_stor08/client/env/env`  ？

不建议。普通外部用户本地不需要这个文件。

客户端会通过这个路径判断是否为内部环境。如果你在本地手动创建了类似内部环境文件，可能导致客户端误判为内部模式，从而使用内部命令集或内部服务地址，最终出现连接失败、鉴权失败等问题。

### Q10：  `ds.cfg`   支持 macOS、Linux、Windows 吗？

支持。客户端通过用户家目录识别配置路径：

```
~/.OREF/ds.cfg
```

在不同系统中，  `~`   会对应当前用户家目录：

- macOS/Linux：  `/Users/<用户名>`   或   `/home/<用户名>`  
- Windows：  `C:\Users\<用户名>`  


### Q11: 无法校验最新版本，命令不能继续执行（Mac/Linux）

```

[ds-cli] 原因 / Reason: <urlopen error timed out>
[ds-cli] 可先尝试升级 / Try updating first:
```

在.bashrc或bash中配置如下内容

```
alias python=python3
alias pip=pip3
export PATH="/Library/Developer/CommandLineTools/usr/bin:$PATH"
export PATH="/Library/Developer/CommandLineTools/usr/bin:$PATH"
```
